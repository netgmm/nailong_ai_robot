## 2. 硬件接线定义与供电方案

### 2.1 典型接线（以裸片 ESP32-S3 + 外设为例）

> 引脚可任意重映射，以下为常用推荐；实际以你的固件配置为准。

| 外设 | 引脚说明 | 建议接法 |
|------|----------|----------|
| 屏幕 ST7789 (SPI) | SCL/SDA/RES/DC/CS/BLK | SCL=IO12, SDA=IO11, RES=IO9, DC=IO10, CS=IO8, BLK=IO7 |
| 麦克风 INMP441 (I2S) | SCK/WS/SD/L-R | SCK=IO15, WS=IO16, SD=IO14, L/R=GND（选左/右声道） |
| 功放 MAX98357A (I2S) | BCLK/LRC/DIN/GAIN | BCLK=IO18, LRC=IO19, DIN=IO17, GAIN 悬空或接地 |

**麦克风 INMP441 引脚**：`VDD→3.3V`、`GND→GND`、`L/R→GND`、`SCK→IO15`、`WS→IO16`、`SD→IO14`。
**功放 MAX98357A 引脚**：`VIN→5V`、`GND→GND`、`BCLK→IO18`、`LRC→IO19`、`DIN→IO17`、`GAIN→GND`（默认增益）。

### 2.2 供电方案

- **主控与数字电路**：3.3V（由板载 LDO 或 IP5306 升压后降压提供）。
- **功放**：MAX98357A 使用 5V 供电，音量大、失真小。
- **电池**：3.7V 锂电池 → 升压模块（IP5306/MT3608）→ 5V 与 3.3V。
- **关键注意**：麦克风与功放务必 **共地**；功放电源与主控电源做好 **去耦电容**（100µF+0.1µF），避免音频电流串扰到模拟/数字地。

## 3. 固件开发选型建议

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **MicroPython** | 上手快、迭代快、有 `urequests`/`machine.I2S` 现成库 | 性能/内存有限，本地模型几乎不可行 | 原型验证 |
| **Arduino (C++)** | 性能好、生态丰富（ESP32 Audio 库）、易量产 | 开发门槛略高、编译链繁琐 | 量产/复杂音频 |
| **ESP-IDF (C)** | 最强性能与资源控制，官方框架 | 门槛最高 | 深度优化/量产 |

> **建议**：原型阶段用 **MicroPython** 快速跑通「联网对话 + 音频」，验证交互；正式量产切换 **Arduino（ESP32 生态）** 以获得稳定的音频处理与更低功耗。

## 4. 当前 PC 端对话逻辑 → ESP32-S3 移植

### 4.1 逻辑本质（与硬件无关）

当前 PC 端核心逻辑只有三步，可原样移植：

1. 构造消息列表 `[{"role":"system",...}, {"role":"user",...}, ...]`（含奶龙人设 + 历史）；
2. HTTP `POST {base_url}/chat/completions`，携带 `Authorization: Bearer <key>`；
3. 解析返回 `choices[0].message.content`。

对应文件：`core/llm_client.py`（请求封装）、`core/conversation.py`（上下文）、`core/personality.py`（人设）。

### 4.2 在 MicroPython 上的移植要点

```python
# 伪代码示意（MicroPython）
import urequests, ujson

def chat(messages):
    url = BASE_URL + "/chat/completions"
    headers = {"Authorization": "Bearer " + API_KEY,
               "Content-Type": "application/json"}
    data = {"model": MODEL, "messages": messages,
            "temperature": 0.8, "max_tokens": 512, "stream": False}
    r = urequests.post(url, headers=headers, data=ujson.dumps(data), timeout=30)
    resp = r.json()
    return resp["choices"][0]["message"]["content"]
```

### 4.3 移植清单

| PC 端模块 | 硬件端实现 |
|-----------|------------|
| `config.yaml` | 固件内常量，或写入 NVS / 文件 |
| `personality.py` | 同样的 system prompt 字符串 |
| `conversation.py` | 内存列表（历史），必要时写 Flash |
| `llm_client.py` | `urequests` / Arduino HTTPClient |
| 网络异常处理 | `try/except` + 断线重连 + 重试 |

### 4.4 建议

- 历史消息条数在硬件上做 **上限截断**（如保留最近 10 轮），节省内存与 token；
- 增加 **断网自动重连** 与 **失败重试（1~2 次）**；
- 网络请求期间显示「奶龙在思考…」的动画/表情。

## 5. 语音唤醒 / 本地 TTS / ASR 两种实现方案

### 5.1 方案一：联网 API 方案（推荐，音质/识别率高）

链路：本地唤醒 → 录音上传云端 ASR → 云端 LLM → 云端 TTS 下载 → 本地播放。

| 环节 | 实现 |
|------|------|
| 唤醒 | 乐鑫 ESP-SR 的 WakeNet（支持自定义唤醒词）或简易能量/静音检测 |
| ASR | 上传音频到 OpenAI Whisper / 讯飞 / 百度 |
| LLM | 直接调用现有 `/chat/completions` |
| TTS | 云端合成后下载 mp3，用 I2S 播放 |

**优点**：效果好、开发快、奶龙声线可用云端音色。
**缺点**：依赖网络、有 API 费用、延迟略高。

### 5.2 方案二：本地轻量化模型方案

| 环节 | 可行性 | 说明 |
|------|--------|------|
| 唤醒 | ✅ 可行 | ESP-SR WakeNet，本地实时唤醒，支持自定义词 |
| ASR | ⚠️ 受限 | ESP32-S3 仅能做 **关键词/命令词识别**（MultiNet，几十~几百条指令），无法本地做开放式长句识别 |
| LLM | ❌ 不可行 | 通用大模型无法跑在 ESP32 上，对话仍须联网 |
| TTS | ⚠️ 受限 | 本地可做 **预录音频拼接**（固定短语），完整语音合成需外接或云端 |

**结论**：ESP32-S3 上「本地完整语音对话」不现实。务实做法是 **混合方案**：
- 本地：唤醒词 + 关键词命令（如「开灯」「讲故事」）；
- 联网：开放式对话的 ASR/LLM/TTS。

若必须完全离线，需换用更强算力主控（如带 NPU 的 Linux 板 / 树莓派 + 本地 Whisper + 本地 TTS）。

## 6. 外壳 3D 打印 / 注塑开模建议

### 6.1 原型：3D 打印

- 工艺：FDM（PLA/树脂）做快速验证，SLA 光固化做外观精致验证；
- 软件：SolidWorks / Fusion360 / FreeCAD 建模，导出 STL；
- 要点：预留 **出音孔、麦克风进音孔（远离喇叭）、USB/充电口、散热孔**；内部分隔腔体防麦克风拾取喇叭声（防啸叫）。

### 6.2 量产：注塑开模

- 前期投入高（模具费数千~数万元），适合批量（千件以上）摊薄成本；
- 建议：先用 3D 打印小批量（几十~几百件）跑通市场，确认需求后再开模；
- 开模注意：拔模角、壁厚均匀、螺丝柱/卡扣、材质（ABS/PC）与表面处理（亲肤手感）。

## 7. 硬件常见问题排查

### 7.1 收音差 / 识别率低

- 换 **INMP441** 数字麦克风，避免模拟麦克风底噪；
- 麦克风远离喇叭、加防风海绵、隔离腔体；
- 检查 I2S 采样率（16kHz）与位深（16bit）配置；
- 增加软件 AGC（自动增益）。

### 7.2 喇叭杂音 / 啸叫

- 用 **I2S 功放（MAX98357A）** 替代模拟功放，减少走线噪声；
- 麦克风与喇叭 **共地**，功放电源加去耦电容；
- 采样率、位深与功放/喇叭匹配；
- 播放与录音 **分时**（半双工），避免回声啸叫。

### 7.3 续航不足

- 增大电池容量（2000mAh+）；
- 开启 **低功耗/深度睡眠**（无交互时休眠，唤醒词唤醒）；
- 关闭屏幕背光或降低亮度、定时熄屏；
- 优化功放功耗（待机关断）。

### 7.4 网络断开处理

- 实现 **WiFi 重连**（断线自动重连、失败指数退避重试）；
- 网络异常时本地缓存 **离线兜底回复**（内置几句奶龙安慰语）；
- 加 **心跳检测**，超时主动重连。
