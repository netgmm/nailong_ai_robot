## 问题 1：TTS 语音合成返回 400 Bad Request（奶龙不说话）

- **现象**：GPT-SoVITS 日志出现 `GET /tts ... 400 Bad Request`，日志里有 `False False False`。
- **原因**：`config.yaml` 里配置的参考音频文件路径不存在（`output\slicer_opt` 目录被清空过），GPT-SoVITS 拿不到参考音频所以拒绝合成。
- **解决**：把 `ref_audio_path` 改成真实存在的音频文件，并保证 `prompt_text` 和该音频实际内容一致。当前可用路径：
  ```
  C:\Users\28567\OneDrive\Desktop\1\GPT-SoVITS-v2pro-20250604\output\slicer_opt\nailong.wav_0000658880_0000887680.wav
  ```

## 问题 2：编译时报 "esp-box 组件找不到 / target 是 esp32"

- **现象**：`Component "espressif/esp-box" has suitable versions for other targets: esp32s3`，提示 `Is your current target esp32 set correctly?`
- **原因**：开发板是 ESP32-S3，但编译目标没设置，IDF 默认按 `esp32` 编译；而 `esp-box` 组件只支持 `esp32s3`。
- **解决**：先设置目标芯片再编译：
  ```powershell
  idf.py set-target esp32s3
  ```
  或 VSCode：`Ctrl+Shift+P` → `ESP-IDF: Set Espressif device target` → 选 `esp32s3`。

## 问题 3：PowerShell 里 `idf.py` 不是可执行命令

- **现象**：`无法将"idf.py"项识别为 cmdlet、函数、脚本文件...`（CommandNotFoundException）。
- **原因**：ESP-IDF 环境没有激活，`idf.py` 不在 PATH 里。
- **解决**：每次新开终端先激活环境（注意 `.` 和路径之间有空格）：
  ```powershell
  . D:\ESP-IDF\v6.0.2\esp-idf\export.ps1
  ```
  若报"禁止运行脚本"：先执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，选 Y，再重新激活。

## 问题 4：set-target 时拒绝清理 build 目录

- **现象**：`Directory '...\build' doesn't seem to be a CMake build directory. Refusing to automatically delete files...`
- **原因**：之前失败/中断的构建留下了残缺的 `build` 目录，IDF 识别不了、不敢自动删。
- **解决**：手动删除后重试：
  ```powershell
  Remove-Item -Recurse -Force .\build
  idf.py set-target esp32s3
  ```

## 问题 5：ESP-IDF v6.0 下找不到 `json` 组件

- **现象**：`Failed to resolve component 'json' required by component 'main': unknown name`
- **原因**：v6.0 把 cJSON 从 IDF 内置组件移到了组件注册表，`REQUIRES json` 不再生效。
- **解决**：
  1. `main/idf_component.yml` 加依赖：`espressif/cjson: "^1.7.16"`
  2. `main/CMakeLists.txt` 里 `json` 改成 `cjson`

## 问题 6：main.c 头文件全部报错（找不到 bsp/lvgl 头文件）

- **现象**：`bsp/esp-bsp.h`、`lvgl.h`、`bsp_board.h` 等全部提示找不到。
- **原因**：依赖组件（esp-box、lvgl、esp_lvgl_port 等）没下载到本地 —— `build/managed_components` 目录不存在。组件没下载，include 路径里自然没有这些头文件。
- **解决**：先 `idf.py set-target esp32s3` 触发组件管理器下载（看 `NOTICE: Processing N dependencies`），再 `idf.py build`。编译通过后，VSCode 里残留的红色波浪线按 `Ctrl+Shift+P` → `Developer: Reload Window` 刷新即可消失。

## 问题 7：编译报 `iot_button_create` 参数不匹配（button 组件版本冲突）

- **现象**：编译 `esp_lvgl_port` 时报：
  ```
  error: too few arguments to function 'iot_button_create'; expected 3, have 1
  ```
- **原因**：`esp_lvgl_port 1.4.0` 用的是 button **旧 API**（`iot_button_create(config)` 单参数），但组件管理器默认解析到了最新版 `espressif/button 4.2.0`（新 API 要传 3 个参数）。版本对不上。
- **解决**：在 `main/idf_component.yml` 里把 button 固定到 3.x（旧 API）：
  ```yaml
  espressif/button: "^3.0.0"
  ```
  （esp-box 3.0.5 要求 `>=2.5`，3.x 满足约束，不冲突）

## 问题 8：button 3.5.0 在 v6.0 下报 `driver/gpio.h: No such file or directory`

- **现象**：编译 `espressif__button/iot_button.c` 时报 `fatal error: driver/gpio.h: No such file or directory`。
- **原因**：button 必须用 3.x（esp-box 3.0.5 和 esp_lvgl_port 1.4.0 用的都是 button 旧 API，4.x 会报参数不匹配）。但 button 3.5.0 的 CMakeLists 只依赖旧 `driver` 组件，而 **v6.0 把 `driver/gpio.h` 挪到了新组件 `esp_driver_gpio`**，所以 include 不到。
- **解决**：给 button 组件补上 `esp_driver_gpio` 依赖（一行补丁）。改 `build/managed_components/espressif__button/CMakeLists.txt`：
  ```cmake
  set(REQ driver esp_driver_gpio)
  ```
  ⚠️ 注意：这个文件在组件管理器目录里，**执行 `fullclean` 后会被重新下载覆盖**，需重新改这一行。

## 问题 9：ESP-IDF 从 v6.0.2 换成 v5.5.5（重要）

- **背景**：v6.0 把 `json` 组件移到注册表、把 `driver` 拆成 `esp_driver_*` 多个组件，导致 esp-box/button 等老组件要打补丁。换成 v5.5.5 后这些拆组件问题**全部不存在**，需要回退 v6.0 的补丁。
- **已回退的改动**：
  1. `main/CMakeLists.txt`：`cjson` → 改回 `json`（v5.x 内置）
  2. `main/idf_component.yml`：删掉 `espressif/cjson` 依赖（v5.x 不需要）
  3. button / esp-box 组件里的 `esp_driver_gpio` 等补丁 → 已还原（v5.x 下这些组件不存在，留着会报错）
- **保留的改动**：`espressif/button: "^3.0.0"`（esp-box/lvgl_port 用 button 旧 API，这个问题和版本无关，必须保留）
- **切版本后必须做**：删除 build 目录 → 重新 `set-target esp32s3` → `build`（build 缓存不跨版本兼容）
- **激活命令也变了**：`. D:\ESP-IDF\v5.5.5\esp-idf\export.ps1`
- ⚠️ 问题 5、8 是 **v6.0 专属**，在 v5.5.5 下不需要这些操作，仅作参考。

## 问题 10：固件报 `bsp_board.h: No such file or directory`（esp-box 3.x API 与旧版不兼容）

- **现象**：编译 `main.c` / `app_audio.c` 时报 `fatal error: bsp_board.h: No such file or directory`。
- **原因**：固件最初按旧版 esp-box **2.x** 的 API 写的（`bsp_board_init` / `bsp_i2s_read` / `bsp_codec_set_fs` / `bsp_btn_register_callback`），而实际下载的 esp-box **3.0.5** 已重构：
  - 音频改为 `bsp_audio_init()` + `bsp_audio_codec_speaker_init()/microphone_init()` + `esp_codec_dev_open/read/write/close`
  - 按键改为 `bsp_iot_button_create()` + `iot_button_register_cb()`
  - `bsp_display_lock()` 返回 `bool`（不是 `esp_err_t`）
  - `bsp_board.h` 已不存在
- **解决**：重写 `app_audio.c` 用 `esp_codec_dev` API；`main.c` 删掉 `bsp_board.h`、按键改用新 API；`app_display.c` 修正 `bsp_display_lock` 判断。CMakeLists REQUIRES 补 `espressif__esp_codec_dev`、`espressif__button`。
- ✅ 已解决，固件编译通过（1.4MB）。

## 问题 11：`app partition is too small`（默认 1MB 分区装不下固件）

- **现象**：编译最后报 `Error: app partition is too small for binary nailong_box.bin size 0x15a550`（factory 分区只有 1MB，固件 1.4MB）。
- **原因**：默认分区表 `factory` 分区只有 0x100000（1MB），带 LVGL + 中文字体的固件装不下。
- **解决**：
  1. 新建 `firmware/partitions.csv`，factory 分区扩到 6MB（0x600000）
  2. `sdkconfig.defaults` 加 `CONFIG_PARTITION_TABLE_CUSTOM=y` + `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"`
  3. ⚠️ 坑：**已经生成过 sdkconfig 的话，defaults 里的新配置不生效**（sdkconfig 优先级高于 defaults）。需要删除 `sdkconfig` 文件后重新 build。
- ✅ 已解决。烧录时因为分区表变了，要 `idf.py erase-flash` 再 `flash`。

## 问题 12：esp-box 3.0.5 触摸驱动 TT21100 在 v5.5.5 下反复崩溃重启（闪屏）

- **现象**：板子反复重启（屏幕一闪一灭），日志报 `TT21100 init failed` / `i2c transaction failed`，`ESP_ERROR_CHECK` 触发 abort。
- **原因**：esp-box 3.0.5 的触摸驱动（TT21100，走 legacy I2C）在 v5.5.5 下 I2C 通信失败。且 Box-3 的触摸屏只用于"虚拟 HOME 主键"，本项目用 GPIO 静音键交互，**根本不需要触摸**。崩溃点有 3 处：
  1. `bsp_display_start_with_config` 里 `bsp_display_indev_init` 初始化触摸输入设备
  2. `bsp_init_main_button` 里主键初始化调 `bsp_touch_new`
  3. `bsp_get_main_button` 里 `assert(tp)`（button 组件轮询主键时触发）
- **解决**：全部跳过触摸（改 `managed_components/espressif__esp-box/esp-box.c`）：
  1. `bsp_display_start_with_config`：`disp_indev = NULL`（不初始化触摸输入设备）
  2. `bsp_init_main_button`：直接 `return ESP_OK`（不调 `bsp_touch_new`）
  3. `bsp_get_main_button`：`tp == NULL` 时直接 `return false`（去掉 `assert(tp)`）
  ⚠️ 这些都是组件目录里的补丁，`fullclean` 后需重改。

## 问题 13：录音时崩溃 `i2s_channel_disable: the channel has not been enabled yet`

- **现象**：第二次录音起报 `E i2s_common: i2s_channel_disable: the channel has not been enabled yet`，伴随 `main: backend failed`（后端失败）。
- **原因**：两个：
  1. **esp_codec_dev 1.1.0 的 open 有 disable bug**：`open` 内部会先无条件 `i2s_channel_disable` 再配置，而 v5.5.5 对已 disable 的通道再 disable 直接报错。我每轮录音/播放都 `open`/`close`，第二轮就触发崩溃。
  2. **录音坏音频 → ASR 失败 → backend failed**：录音通道状态错乱导致录出坏音频，后端 faster-whisper 识别失败返回 error，板子打印 `backend failed`。
- **解决**（重写 `main/app_audio.c`）：
  1. **open 一次、复用，不反复 open/close**（init 时 open mic+spk，录音直接 read、播放直接 write）。
  2. **采样率统一 32k**：GPT-SoVITS 输出固定 32000Hz，录音也改 32k（共享 I2S 时钟必须一致）；faster-whisper 会自动重采样到 16k 识别，不受影响。
  - `AUDIO_SAMPLE_RATE` 从 16000 → 32000。

## 问题 14：后端 200 但 GPT-SoVITS 从没收到 /tts（用错 Python 环境）

- **现象**：后端日志 `POST /voice 200 OK`，但 GPT-SoVITS 日志里只有 `GET /docs`，从没收到 `GET /tts`；板子 `backend failed`。
- **原因**：用 `python main.py` 启动后端，而系统 `python` 是 **Anaconda**（`D:\anaconda\python.exe`），**没装 faster-whisper**。ASR 懒加载，启动时不报错，但 `/voice` 一调 ASR 就 `ModuleNotFoundError`，被捕获返回 error（HTTP 200 + error 字段），**没走到 DeepSeek 和 TTS**。
- **解决**：用 `.venv` 启动后端（faster-whisper 1.2.1 装在 .venv 里）：
  ```powershell
  .\.venv\Scripts\python.exe main.py
  ```
- ✅ 已解决（验证：`.venv` 有 faster_whisper 1.2.1，Anaconda 没有）。

## 问题 15：板子 `ESP_ERR_HTTP_EAGAIN` 超时（后端处理太慢）

- **现象**：板子日志 `Connection timed out before data was ready` + `HTTP perform failed: ESP_ERR_HTTP_EAGAIN` + `backend failed`。
- **原因**：换 .venv 后 ASR 真正工作了，但后端第一次处理 `/voice` 太慢——faster-whisper 首次加载模型（base 145MB，5~20s）+ 识别 5 秒音频（3~8s）+ DeepSeek + TTS，合计可能超过板子固件的 **30 秒 HTTP 超时**（`timeout_ms = 30000`）。
- **解决**（两个一起做）：
  1. **板子超时加大**：`app_backend.c` 的 `timeout_ms` 从 30000 → 120000。
  2. **后端预热模型**：`asr.py` 加 `warmup()`，`main.py` 启动时提前加载 faster-whisper，消除首次请求的模型加载耗时。
- ✅ 已修复（需重新编译烧录板子 + 重启后端）。

## 问题 16：后端返回 1.4MB 音频，板子读响应失败（backend failed）

- **现象**：后端 `/voice` 返回 200，响应里 `audio_base64` 有 **1.4MB**（实测 `Content-Length: 1382834`），但板子 `backend failed`，且无具体错误日志（静默失败）。
- **原因**：板子原来用 `esp_http_client_read_response` + 固定 buffer（`content_len` 兜底只有 64KB）读响应。响应含 1.4MB 的 base64 音频，`read_response` 读大响应失败（`read_len <= 0`，静默返回 ESP_FAIL）。
- **解决**：改用**事件回调**（`HTTP_EVENT_ON_DATA`）动态累积响应数据（`realloc` 动态扩容），任意大小的响应都能正确接收。重写 `app_backend.c` 的响应读取部分。
- ✅ 已修复（需重新编译烧录板子）。

## 问题 17：后端返回「未识别到有效语音内容」（麦克风增益未设置）

- **现象**：链路已通（板子能读到后端响应），但后端返回 `backend error: 未识别到有效语音内容`，ASR 识别结果为空。
- **原因**：`app_audio.c` 里**漏了麦克风输入增益** `esp_codec_dev_set_in_gain()`。不设置时默认增益太低，录到的声音过小，faster-whisper 识别不出内容。
- **解决**：在 `app_audio_init()` 里加 `esp_codec_dev_set_in_gain(s_mic, 50.0)`（官方示例默认值）。
- ✅ 已修复（需重新编译烧录板子）。

## 问题 18：ASR 识别为空（ES7210 双麦克风声道问题）

- **现象**：增益提到 50/70 都无效，ASR 一直「未识别到有效语音内容」。
- **原因**：两个关键事实：
  1. ES7210 最大硬件增益只有 **37.5dB**，设 50/70 都被 `get_db()` 钳制到 37.5dB——增益早就到顶了，**不是增益问题**。
  2. ES7210 是**双麦克风**（MIC1+MIC2 立体声输出），录音却按 mono 处理。esp_codec_dev 1.1.0 的 mono 声道抽取（channel_mask）在 v5.5.5 下不可靠，导致录到错误/静音数据。
- **解决**：麦克风改用 **stereo（channel=2）录音**，读 2 通道交错数据，再**手动抽取左声道**（每 4 字节 `L_lo L_hi R_lo R_hi` 取前 2 字节）。扬声器仍用 mono。
- ✅ 已修复（需重新编译烧录板子）。

## 问题 19：播放音调变尖 + ASR 识别不清楚

- **现象**：语音播放音调变尖（像快进），且用户说话识别不清楚。
- **原因**（两个）：
  1. **音调变尖**：麦克风改成 stereo（channel=2）后，扬声器仍是 mono（channel=1），mic/spk 声道不一致导致 esp_codec_dev 计算 I2S slot 宽度错误（spk 被配成 32bit slot 而数据是 16bit），播放数据错位、音调变尖。
  2. **识别不清楚**：faster-whisper 用的 `base` 模型对中文精度不够。
- **解决**：
  1. 扬声器也改成 **stereo（channel=2）**，播放时把 GPT-SoVITS 的 mono 音频**复制成左右声道相同**再写。
  2. `config.yaml` 的 `asr.model_size` 从 `base` → `small`（更准，首次要下载约 500MB 模型）。
- ✅ 已修复（固件需重烧 + 后端需重启）。

## 问题 20：麦克风录到全 0（用错 BSP，I2S 字同步引脚 LCLK 配错）

- **现象**：板子录音 `[debug] 左右声道 RMS 都 = 0`，后端 ASR 一直返回「未识别到有效语音内容」。换按键、加增益、改声道、彻底断电重启都无效；但刷回官方出厂固件能语音唤醒（说明麦克风硬件是好的）。
- **原因**：**用错了 BSP 组件**。板子是 ESP32-S3-Box-3，但 `idf_component.yml` 里用的是 `espressif/esp-box 3.0.*`（这是老款 ESP32-S3-Box 的 BSP），正确应该用 `espressif/esp-box-3`。两个 BSP 引脚定义不同：老 esp-box 把 **I2S 字同步时钟 LCLK 配成 GPIO47**，但 Box-3 实际是 **GPIO45**（LCD 背光也反了：45↔47）。WS 时钟打错脚 → ES7210 收不到帧同步 → 不吐数据 → 录到全 0。
- **解决**：改 `managed_components/espressif__esp-box/include/bsp/esp-box.h` 两个引脚：
  - `BSP_I2S_LCLK`：47 → 45
  - `BSP_LCD_BACKLIGHT`：45 → 47
- **⚠️ 关键坑**：改 `managed_components` 里的头文件后，普通 `idf.py build`（增量编译）**不会重新编译 esp-box 组件**，改动不生效；必须 `idf.py fullclean` 再 `idf.py build`（全量重编）才真正编进去。
- ✅ 已解决（整链路跑通）。
