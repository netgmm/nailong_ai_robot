# 语音功能扩展方案

> 本文档说明如何在当前文字对话 Demo 基础上，完整加入「语音输入 + 语音输出」能力。
> 当前工程已在 `main.py` 中预留两处接口调用点，并在 `interfaces/` 下提供 `asr.py` / `tts.py` 占位接口。

## 一、整体链路

```
[麦克风] → [ASR 语音转文字] → [文字对话核心(现有)] → [TTS 文字转语音] → [喇叭]
              recognize_speech()                              synthesize_speech()
```

接入语音后，核心对话逻辑（人设、多轮记忆、模型调用）完全复用，无需改动。

## 二、接入位置

1. **语音输入**：`main.py` 主循环中「【ASR 语音输入预留点】」处，将键盘 `input()` 替换为：

```python
user_input = recognize_speech()        # 返回识别出的文本
print(f"你（语音）：{user_input}")
```

2. **语音输出**：`main.py` 中「【TTS 语音输出预留点】」处，在打印回复后调用：

```python
synthesize_speech(reply)               # 将回复合成语音并播放
```

## 三、ASR（语音转文字）实现建议

在 `interfaces/asr.py` 中补全 `recognize_speech()` 函数体。

### 方案 A：云端 API（推荐，音质/准确率高）

| 服务 | 说明 |
|------|------|
| OpenAI Whisper API | 多语言、准确率高，`openai.Audio.transcriptions` |
| 讯飞语音听写 | 中文效果好，需申请 AppID/APIKey |
| 百度 / 阿里 / 腾讯 | 均有 REST 接口，中文识别成熟 |

实现要点：
- 使用 `sounddevice` / `pyaudio` 采集麦克风 PCM 音频；
- 按各厂商要求格式（采样率 16kHz、单声道）上传；
- 将返回文本 `return`。

### 方案 B：本地模型（离线、隐私好）

| 方案 | 说明 |
|------|------|
| faster-whisper | Whisper 的加速版，CPU 可跑 small/base 模型 |
| Vosk | 轻量，支持流式识别，适合中英文 |

实现要点：
- 首次运行下载模型文件；
- 麦克风采集 → 送入模型 → 返回文本。

## 四、TTS（文字转语音）实现建议

在 `interfaces/tts.py` 中补全 `synthesize_speech()` 函数体。

### 方案 A：云端 API

| 服务 | 说明 |
|------|------|
| OpenAI TTS | `openai.Audio.speech`，音质自然 |
| 讯飞 / 百度 / 阿里 | 中文音色丰富，支持语速/音调调节 |
| 微软 Azure TTS | 音色自然，支持 SSML |

实现要点：
- 调用接口返回音频字节（mp3/wav）；
- 用 `sounddevice` / `pygame` / `playsound` 播放。

### 方案 B：本地模型（推荐用于奶龙声线定制）

| 方案 | 说明 |
|------|------|
| edge-tts | 免费、无需密钥、中文音色自然 |
| GPT-SoVITS | 可克隆「奶龙」声线，做专属音色（需单独训练） |

实现要点：
- GPT-SoVITS 需准备奶龙音色样本 → 训练 → 得到声线模型；
- 推理时：文本 → 合成音频 → 播放。

## 五、声线定制（GPT-SoVITS）简要流程

1. 收集奶龙干净语音样本（建议 1 分钟以上、无明显背景噪声）；
2. 安装 GPT-SoVITS 并训练（参考其官方文档）；
3. 导出推理模型；
4. 在 `synthesize_speech()` 中调用推理接口，传入奶龙声线模型路径；
5. 播放合成结果。

## 六、注意与约束

- 本阶段「语音采集/播放」不在文字 Demo 内实现，仅预留接口，避免引入音频库依赖影响文字对话的轻量可运行性。
- 新增依赖（如 `pyaudio` / `sounddevice` / `pygame`）建议按需补充到 `requirements.txt`，或使用独立的 `requirements-voice.txt` 区分。
